# Mac 网络出口小组件 设计方案（草案 v0.1）

> 场景：经常多地出差，工作上主要用**全局代理 + 固定出口 IP**，也会切换各类代理。
> 目标：在菜单栏一眼看清「我现在从哪个 IP 出去、它在哪、和我本地是否一致、网速多少」，出口异常时第一时间知道。

---

## 1. 要解决的问题

| 风险 / 需求 | 说明 |
|---|---|
| 出口不是预期的固定 IP | 代理切错节点、节点故障自动切换、订阅更新后 IP 变了 |
| 代理掉线，变成直连 | 全局代理断开或 TUN 失效，流量从本地真实 IP 出去，自己却不知道 |
| 时区不一致 | 出口 IP 所在时区、Mac 系统时区、人所在地三者不一致，可能影响工作账号风控或排期判断 |
| 实时网速 | 判断当前代理线路是否卡顿 |

核心思路：**你用的是固定 IP，所以“预期出口”是已知的**。组件最重要的能力不是“查 IP”，而是“对照白名单判断出口对不对”。

---

## 2. 功能设计

### 2.1 菜单栏（常驻，一眼看懂）

```
🟢 🇯🇵 东京-固定A  ↓2.3M ↑180K
```

- **状态灯**：🟢 出口在白名单内 / 🟡 出口不在白名单（未知节点） / 🔴 疑似直连或无法联网
- **国旗 + 出口标签**：命中白名单时显示你起的名字（如「东京-固定A」），否则显示国家代码
- **实时上下行网速**：每秒刷新
- 可选精简模式：只显示状态灯和国旗

### 2.2 点开面板（细节）

```
出口（走代理）
  IP        203.0.113.10   ✅ 东京-固定A
  位置      日本 · 东京 · ExampleISP / AS64500
  时区      Asia/Tokyo（当地 15:48 → 16:48）

本机
  系统时区  Asia/Shanghai（15:48）
  网卡      utun4（TUN） / en0 Wi‑Fi
  直连 IP   见 4.2（全局代理下可能查不到）

网速
  实时      ↓2.3 MB/s  ↑180 KB/s
  近 5 分钟 迷你折线图
  [测一次带宽]（手动，会消耗流量）

[立即刷新]  [复制出口 IP]  [编辑白名单]  [查看变化记录]
```

### 2.3 白名单（固定 IP 档案）

配置文件 `~/.config/netwidget/exits.json`（v1 改用 JSON：标准库即可解析，兼容 macOS 自带 Python 3.9，不需要装 YAML 库）：

```json
{
  "exits": [
    {"ip": "203.0.113.10", "label": "东京-固定A", "expect_tz": "Asia/Tokyo"},
    {"ip": "198.51.100.22", "label": "新加坡-固定B", "expect_tz": "Asia/Singapore"}
  ],
  "real_ip_hints": ["192.0.2.0/24"]
}
```

`real_ip_hints` 是你的直连网络出口网段，命中就判定为“裸奔”（示例为文档专用网段，按实际填写）。

### 2.4 告警（系统通知）

| 事件 | 通知内容 |
|---|---|
| 出口 IP 变了 | 「出口已从 东京-固定A 切换到 新加坡-固定B」 |
| 出口不在白名单 | 「当前出口 x.x.x.x（美国）不在你的固定 IP 列表」 |
| 疑似直连 | 「代理可能已断开，当前出口为本地网络」 |
| 出口时区 ≠ 系统时区 | 只在面板里标黄，不弹通知（出差时很常见，避免打扰） |

同一事件 10 分钟内不重复提醒。

### 2.5 变化记录

本地保存最近 200 条出口变化：时间、旧 IP→新 IP、标签。方便事后回看“什么时候掉过线”。

---

## 3. 时区怎么处理

- **出口时区**：IP 查询接口直接返回（如 `Asia/Tokyo`），白名单里也可写死 `expect_tz` 作为兜底
- **系统时区**：读 macOS 当前时区；建议在系统设置里打开「根据位置自动设置时区」，组件只显示、不修改
- 面板同时显示两地当前时间，出差排会时直接看

---

## 4. 技术方案

### 4.1 出口 IP 和地理信息

- 走系统网络（即走全局代理）请求 IP 查询接口，**至少 2 个来源互为备份**，例如 ipinfo.io、ip-api.com、ipwho.is，结果不一致时以多数为准
- 刷新策略：每 60 秒查一次；检测到网卡/路由变化（切代理、换 Wi‑Fi、唤醒）时立即查
- 结果缓存，同一 IP 的地理信息缓存 24 小时，避免触发接口限流
- 命中白名单时可**不依赖外部接口**也能显示标签（只需拿到 IP）

### 4.2 直连 IP 的难点（全局代理下）

全局代理（尤其 TUN 模式）会接管所有流量，普通程序**拿不到绕过代理的直连 IP**。可选方案：

1. **读代理客户端的接口**（推荐）：Clash / mihomo、Surge 等都有本地控制接口，可以直接读“当前节点名、代理是否开启”，比查 IP 更准、更快
2. 在代理规则里给某个查询域名设置 `DIRECT`，组件用它查直连 IP
3. 不查直连 IP，只用 `real_ip_hints` 判断出口是否落在本地网络段

v1 先做 3，再按你用的代理客户端加 1。

### 4.3 网速

- 读系统网卡收发字节计数，每秒做差值，**不产生额外流量**
- 全局代理 TUN 模式下优先统计物理网卡（en0 等），避免 utun 与物理网卡重复计数
- 带宽测速做成手动按钮，下载固定大小文件（约 10–25MB）测一次

### 4.4 实现路线

| 阶段 | 形式 | 工作量 | 说明 |
|---|---|---|---|
| v1 | [SwiftBar](https://github.com/swiftbar/SwiftBar) 插件（Python/Shell 脚本） | 半天 | 菜单栏 + 下拉面板 + 通知 + 白名单，先用起来 |
| v2 | 接入代理客户端控制接口 | 半天 | 显示节点名、代理开关状态，判断更准 |
| v3（可选） | 原生 Swift 菜单栏应用 + 桌面小组件 | 1–2 天 | 更好看、可分享；需处理签名与公证 |

---

## 5. 隐私与安全

- 所有数据只存本机，不上传
- IP 查询接口会看到你的出口 IP（这本来就是公开的），不发送其他信息
- 白名单文件含真实 IP，建议不放进同步盘或公开仓库

## 7. 针对 Quantumult X（Mac）的修订（v0.2）

你主力客户端是 **Quantumult X（Mac）**，这会直接改写方案第 4.2 / 4.4 节。

### 7.1 和 Clash / Surge 的关键差别

| 能力 | Clash / mihomo / Surge | Quantumult X Mac |
|---|---|---|
| 本地 HTTP/SOCKS 端口 | 有（如 7890） | **没有**，走 TUN / NETunnel 接管系统流量 |
| 控制接口读「当前节点名 / 是否开启」 | 有 REST API | **没有现成的状态 API** |
| 自定义本地接口 | — | 有 `[http_backend]`，默认 `http://127.0.0.1:9999/...`，需自己写 JS 脚本暴露数据 |
| 查出口 IP | 走代理端口即可 | 组件直接请求外网 IP 接口，流量会自然走 QX TUN |

结论：**不能指望像 Clash 那样读「当前选了哪个节点」**。对固定 IP 场景，**以出口 IP 对白名单为主**反而更合适——固定 IP 关心的是「出去的 IP 对不对」，不是「节点名字叫什么」。

### 7.2 修订后的判断逻辑（v1）

1. 组件直接请求 IP 查询接口（流量经 QX TUN）→ 得到当前出口 IP  
2. 和 `exits.json` 白名单比对：  
   - 命中 → 🟢 显示标签（如「东京-固定A」）  
   - 未命中 → 🟡 未知出口，弹通知  
   - 命中 `real_ip_hints`（你的直连网段）→ 🔴 疑似裸奔 / 代理掉线  
3. 辅助信号（可选，不依赖 QX API）：  
   - 进程是否在跑（`Quantumult X`）  
   - 是否存在 `utun*` 类虚拟网卡（TUN 是否起来）  
   - 两者都无 + 出口落在直连网段 → 高置信「代理未开」

### 7.3 关于直连 IP

QX Mac 全局 TUN 下，组件很难绕开代理查「真实本地出口」。v1 **不查直连 IP**，只用：

- 固定 IP 白名单（对上了就安心）  
- `real_ip_hints`（对上了就报警）  

若以后一定要在 QX 里暴露状态，可探索 `[http_backend]` 自写脚本，但官方没有「当前策略 / 当前节点」的稳定公开字段，**不作为 v1 依赖**。

### 7.4 实现路线调整

| 阶段 | 内容 | 说明 |
|---|---|---|
| v1 | SwiftBar 插件：查出口 IP + 白名单 + 网速 + 通知 | **不依赖 QX API**，和客户端解耦，换代理也能用 |
| v1.5 | 检测 QX 进程 / TUN 网卡，辅助判断「代理是否开着」 | 轻量，提高掉线识别准确度 |
| v2（可选） | 若你愿意维护一段 QX `[http_backend]` 脚本，再尝试暴露更多内部状态 | 收益不确定，先不做 |

### 7.5 和你用法的匹配度

全局代理 + 固定 IP 居多 → **白名单模式最贴**：你心里清楚「工作该用哪几个 IP」，组件只负责盯这几个有没有变。节点名字、策略组切换对你反而不如「IP 对不对」重要。

## 8. v1 实现说明（与上文的差异）

- 配置格式：YAML → **JSON**（`~/.config/netwidget/exits.json`），`exits[].ip` 额外支持 CIDR 网段。
- 出口查询分两步：先用轻量接口查 IP（ipify → checkip.amazonaws.com），再按 IP 查地理（ipwho.is → ip-api.com → ipinfo.io），逐个回退；地理信息按 IP 缓存 24 小时。v1 未做「多数表决」交叉校验。
- 刷新：SwiftBar 每 10 秒运行一次（网速为 10 秒平均），出口 IP 10 秒查一次（v1 初版为 60 秒，后改为 10 秒）；未做“网卡/路由变化时立即查”，可点「立即刷新」。
- TUN 检测只认带 IPv4 地址的 utun（macOS 默认的 utun0~3 不算）。
- 未做：直连 IP 查询、手动带宽测速、5 分钟折线、精简模式开关。
